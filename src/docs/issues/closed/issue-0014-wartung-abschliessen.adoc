== Beschreibung

WartungService.wartungAbschliessen(): setzt einen wartungsfälligen Gegenstand auf verfügbar und den Nutzungszähler auf null. Wartungsfällige Gegenstände werden nie ausgegeben oder reserviert (BR-WA-04, bereits in Issue 0007/0018 durchgesetzt — hier nur der Zustandswechsel zurück).

== Akzeptanzkriterien

[source,gherkin]
----
# BR-WA-03
Szenario: Wartung setzt Zähler zurück
  Angenommen ein Gegenstand ist wartungsfällig
  Wenn der Wart die Wartung abschließt
  Dann wechselt der Gegenstand in den Zustand "verfügbar"
  Und der Nutzungszähler wird auf null gesetzt
----

== Abhängigkeiten

- 0012 (Nutzungszähler und Wartungsfälligkeit)

== Analyse

* Neuer `WartungService` (analog `RueckgabeService`, ein Service je fachlichem Vorgang, ADR-0003).
* `wartung_abschliessen(gegenstand_id, rolle="wart")`: Vorbedingung `gegenstand.zustand == "wartungsfaellig"` (sonst `ConflictError`), `rolle == "wart"` (sonst `ValidationError`, code `FORBIDDEN`), unbekannte ID -> `NotFoundError`.
* Zustandswechsel über bestehende `GegenstandRepository.zustand_wechseln_atomar(id, "wartungsfaellig", "verfuegbar", version)`.
* Neue Repository-Methode `GegenstandRepository.nutzungszaehler_zuruecksetzen(gegenstand_id)` (`UPDATE gegenstand SET nutzungszaehler = 0 WHERE id = ?`), aufgerufen nach erfolgreichem Zustandswechsel.
* CLI-Befehl `leihgut wartung abschliessen --gegenstand <id> --rolle wart` (SUC-08), Exit-Codes 0/1/2 exakt wie in system-use-cases.adoc, analog zum bestehenden `pruefung abschliessen`-Befehl.
* Tests: neues `tests/test_wartung_service.py` + CLI-Test in `tests/test_cli.py`; TDD-Referenz BR-WA-03, BR-WA-04 (Negativtest: Ausgabe eines wartungsfälligen Gegenstands bereits durch bestehenden BR-AUS-01-Check abgedeckt, hier nur Zustandsübergang selbst testen).
